# 1. 项目介绍

## 1.1 项目背景及意义

当前，传统求职流程主要存在以下问题：
- 对于求职者：
>1. 缺乏对自身能力与职业方向的清晰认知；
>2. 面对海量岗位信息，筛选成本较高；
>3. 岗位信息获取与岗位选择缺乏主动性；
>4. 缺乏个性化、持续性的职业发展建议。
- 对于招聘市场：
>1. 岗位信息来源分散，整合效率较低；
>2. JD（Job Description）文本复杂，岗位核心需求难以快速提取；
>3. 岗位技能要求具有较强的语义特征，传统关键词方法难以实现精准匹配。

针对上述问题，本项目设计并开发了一套基于大语言模型（Large Language Model，LLM）的 AI 求职助手系统，通过 LLM 的语义理解与推理能力，实现从 “用户画像—职业规划—岗位采集—人岗匹配—数据分析” 的一体化求职辅助，为求职者提供更加精准、主动和个性化的职业决策支持。

## 1.2 项目简介

本项目主要利用 Python、Streamlit、LangChain、DrissionPage、Pandas、Seaborn 等技术，构建一个集用户画像、职业规划、岗位采集、智能匹配与数据可视化于一体的 AI 求职助手系统。

该系统主要由五个子系统组成：用户画像生成系统、AI 职业规划助手系统、招聘岗位自动采集系统、岗位-人才智能匹配评分系统、岗位数据可视化系统。

1. **用户画像生成系统**：基于简历、偏好问答等数据，利用 LLM 构建结构化用户画像；
2. **AI 职业规划助手系统**：结合用户画像与发展需求，为用户提供职业方向分析与发展建议；
3. **招聘岗位自动采集系统**：自动化采集招聘平台中的岗位信息，并对岗位数据进行结构化处理；
4. **岗位-人才智能匹配评分系统**：利用 LLM 对用户画像与岗位数据进行语义层面的深度匹配，并从能力、职责、发展、背景及潜力五个维度进行综合评分；
5. **岗位数据可视化系统**：通过数据分析与可视化技术，对岗位分布、薪资、匹配得分及岗位特征等信息进行多维度展示，为求职决策提供数据支持。

五大子系统以 “用户画像” 为核心，以 “职业规划” 为引导，以 “岗位采集” 为数据基础，通过 “智能匹配” 实现人岗连接，并以 “数据可视化” 形成分析反馈与决策闭环。

本项目旨在利用 LLM 的语义理解、推理与生成能力，替代传统求职系统中较为单一的关键词匹配方式，提升岗位匹配的语义理解能力、个性化程度与可解释性，帮助求职者更加深入地认识自身能力与职业需求，实现人与岗位的精准匹配，从而降低求职过程中的时间与精力成本，提高职业选择效率，并促进人力资源的合理配置与社会价值创造。

# 2. 项目具体介绍

该项目的系统主要由 “用户画像生成系统、AI 职业规划助手系统、招聘岗位自动采集系统、岗位-人才智能匹配评分系统、岗位数据可视化系统” 这五个子系统组成，从而形成 “用户画像—职业规划—岗位采集—人岗匹配—数据分析” 的一体化求职辅助服务。

## 2.1 用户画像生成系统

用户画像生成系统是整个 AI 求职助手系统的核心模块，其目标是将求职者分散、非结构化的个人信息转化为结构化、可分析、可用于后续推理的职业画像。

该系统首先获取用户简历中的基本信息、教育背景、专业技能、项目经历、工作经历等信息进行重新总结，并结合用户的偏好选择，利用 LLM 对用户输入内容进行语义理解、信息提取与归纳，并从教育背景、专业能力、工作经历、项目经验、职业兴趣、求职偏好及发展潜力等多个维度构建用户画像。其后，根据用户画像，系统会自动生成职场报告和精准的岗位检索关键词。职场报告将被封装为上下文提示词（System Context Prompt），注入到 AI 职业规划助手的推理工作流中。岗位检索关键词将用于指导招聘岗位自动采集系统进行岗位采集。

该系统旨在解决求职者职业定位不清、对自身能力与适配岗位认知不足的问题，为后续的智能职业规划与精准岗位推荐奠定了坚实的数据基础。

![[Pasted image 20260813120938.png]]

## 2.2 AI 职业规划助手系统

AI 职业规划助手系统主要面向用户的职业咨询与求职决策，为用户提供基于个人情况的职业分析和规划建议。系统以用户画像生成系统输出的职场报告为基础，将其中的教育背景、专业技能、项目经历、工作经验、职业兴趣和求职偏好等信息作为后续推理过程的重要上下文。

该系统在用户提出职业相关问题后，首先对问题进行语义理解，再结合用户职场报告进行分析。例如，对于“适合从事哪些岗位”、“适合去哪些城市工作”、“目前还需要补充哪些能力”等问题，系统会根据用户已有经历进行针对性回答，而非直接给出通用的职业建议。

该系统旨在解决求职者职业方向不清、缺乏个性化规划和求职决策依据不足的问题，为职业定位、发展规划与求职决策提供个性化支持。

![[Pasted image 20260813122024.png]]

## 2.3 招聘岗位自动采集系统

招聘岗位自动采集系统主要负责获取与用户职业方向相关的招聘岗位信息，为后续岗位匹配、智能评分和数据分析提供实时采集的岗位数据。

该系统以用户画像生成系统输出的岗位检索关键词为依据，利用网络爬虫技术自动采集岗位名称、公司名称、岗位职责、任职要求、薪资待遇、工作地点、学历要求及经验要求等信息，并对原始岗位数据进行清洗、去重和结构化处理，为后续岗位匹配与分析提供标准化数据。

该系统旨在降低人工检索岗位的时间成本，实现招聘岗位信息的自动化获取与结构化管理，为用户精准筛选岗位提供数据基础。

![[Pasted image 20260813123437.png]]

## 2.4 岗位-人才智能匹配评分系统

岗位-人才智能匹配评分系统主要负责评估用户职业画像与招聘岗位之间的匹配程度，为后续岗位筛选、排序、可视化提供数据支持。

该系统结合用户画像与岗位信息，利用 RAG 检索和 LLM 推理能力，从能力、岗位职责、职业发展、个人背景及发展潜力等维度进行综合分析，并生成岗位匹配得分（包含：总得分、能力得分、职责得分、发展得分、背景得分、潜力得分）、推荐理由、匹配优势、待提升项、及发展建议。

该系统旨在降低求职者从海量岗位中筛选合适岗位的难度，是岗位选择的量化、个性化依据。

![[Pasted image 20260813125104.png]]

## 2.5 岗位数据可视化系统

岗位数据可视化系统主要负责对招聘岗位数据及岗位匹配结果进行统计分析与可视化展示，为用户了解岗位市场特征、比较岗位差异及辅助岗位选择提供数据支持。

该系统以招聘岗位自动采集系统和岗位-人才智能匹配评分系统产生的数据为基础，从岗位数量、薪资水平、工作地点、学历要求、经验要求、行业分布及岗位匹配得分等维度进行统计分析，并通过柱状图、散点图、雷达图等方式直观展示岗位数据。。在支持全岗位分析的同时，系统也支持对单个岗位进行多维度分析，展示岗位基本信息、匹配得分及各维度匹配情况，帮助用户更加直观地了解岗位特点与自身匹配程度。

该系统旨在降低岗位数据的理解和比较成本，将复杂的岗位信息转化为直观的可视化结果，为岗位筛选、就业市场分析及求职决策提供数据依据。

# 3. 系统架构设计

本系统采用模块化、分层设计，以用户画像为核心，以 LLM 为主要智能分析引擎，整合用户画像、职业规划、岗位采集、人岗匹配和数据可视化等功能，形成完整的 AI 求职辅助流程。

系统整体流程为：用户简历与偏好 → 用户画像 → 职业规划与岗位关键词 → 岗位自动采集 → 数据处理与 RAG 检索 → LLM 智能匹配 → 岗位评分 → 数据可视化 → 求职决策。

其中，用户画像连接职业规划和岗位采集，岗位采集为智能匹配提供数据基础，LLM 负责语义理解与匹配分析，数据可视化用于展示岗位市场及匹配结果，最终形成从用户分析、岗位获取到智能匹配和决策支持的完整闭环。

系统整体架构可以划分为用户交互层、业务功能层、智能分析层、数据处理层和基础支撑层五个层次，各层之间通过统一的数据结构和模块接口进行衔接，从而保证系统具有较好的可维护性和扩展性。

![[Pasted image 20260813132406.png]]

## 3.1 用户交互层

用户交互层主要基于 Streamlit 实现，为用户提供简历上传、个人偏好填写、职业咨询、岗位采集参数设置、岗位匹配结果查看以及数据可视化分析等功能。

用户可以通过可视化界面完成从个人信息输入到岗位筛选的全过程，无需直接操作底层模型、爬虫或数据处理程序。

## 3.2 业务功能层

业务功能层由五个核心子系统组成：

1. 用户画像生成系统：负责解析用户简历和偏好信息，构建结构化职业画像；
2. AI 职业规划助手系统：负责根据用户画像回答职业相关问题，并提供职业发展建议；
3. 招聘岗位自动采集系统：负责根据岗位检索关键词获取招聘岗位数据；
4. 岗位-人才智能匹配评分系统：负责计算用户与岗位之间的多维度匹配程度；
5. 岗位数据可视化系统：负责对岗位市场数据和匹配结果进行统计分析和可视化展示。

五个子系统之间通过统一的数据结构进行衔接，使各功能模块既能够独立运行，又能够协同工作。

## 3.3 智能分析层

智能分析层是系统区别于传统求职平台的核心部分，主要由 LLM、RAG 和 Prompt 工程组成。

用户画像生成过程中，LLM 对简历文本、用户偏好等非结构化信息进行语义理解和信息归纳；职业规划过程中，LLM 结合用户职场报告进行个性化推理；岗位匹配过程中，则结合用户画像和岗位信息进行语义层面的深度分析。

同时，通过 RAG 对岗位数据进行检索和筛选，减少无关岗位直接进入 LLM 推理过程，在降低模型调用成本的同时，提高岗位分析效率。

## 3.4 数据处理层

数据处理层主要负责简历数据和招聘岗位数据的预处理。

对于简历数据，系统首先根据 PDF 类型提取文本；对于无法直接提取文本的 PDF，则进一步采用 OCR 方式识别页面内容。

对于招聘岗位数据，则依次进行字段提取、数据清洗、异常值处理、格式统一和重复数据删除，将不同来源的原始岗位信息转换为统一的数据结构。

处理后的数据进一步用于 RAG 检索、LLM 匹配评分以及后续统计分析。

## 3.5 基础支撑层

基础支撑层主要包括 Python 运行环境、LangChain、数据处理与可视化组件以及网络自动化组件等，为上层业务功能提供基础支持。

其中：
- Python：作为系统主要开发语言；
- Streamlit：负责系统 Web 界面和交互功能；
- LangChain：负责 LLM 应用流程及 RAG 等功能的组织；
- DrissionPage：用于招聘网站自动化访问和岗位信息采集；
- Pandas、NumPy：用于岗位数据清洗、统计和分析；
- Matplotlib、Seaborn：用于岗位数据和匹配结果可视化。

通过上述分层设计，实现了界面、业务逻辑、智能分析和数据处理之间的相对解耦，为后续功能扩展提供了基础。

# 4. 技术架构

本项目采用 Python 作为主要开发语言，并结合 LLM、RAG、Web 自动化、数据分析和可视化等技术构建完整的 AI 求职助手。
![[Pasted image 20260813135552.png]]

## 4.1 LLM 技术

大语言模型是系统实现智能理解和推理能力的核心技术。利用 LLM 将关键词匹配进一步扩展到语义理解、能力推断和职业发展分析。例如，用户简历中描述 “利用 Python 完成实验数据处理与自动化分析”，岗位中描述 “负责数据处理及分析工具开发”，即使二者不存在完全一致的关键词，LLM 仍可以根据上下文判断二者之间的能力关联。

## 4.2 RAG 技术

在岗位匹配过程中，如果将大量岗位数据全部直接输入 LLM，不仅会增加 Token 消耗，也会降低模型处理效率。因此，本系统引入 RAG 技术，对岗位数据进行检索和筛选。

其基本流程为：岗位数据 → 文档化 → 向量化 / 建立检索索引 → 根据用户画像进行检索 → 获取相关岗位 → LLM 深度评分。

通过 RAG，可以先从大量岗位中筛选出与用户职业方向相关的岗位，再将有限数量的候选岗位交给 LLM 进行深度分析，从而实现 “先检索、后推理”。

## 4.3 Prompt 工程

为了提高 LLM 输出结果的稳定性，本系统对不同任务分别设计对应的 Prompt。

例如，用户画像生成任务要求模型从教育背景、专业能力、工作经历、项目经验、职业兴趣和求职偏好等维度提取信息；岗位匹配任务则要求模型严格按照能力、职责、发展、背景和潜力五个维度进行评分。

同时，通过结构化输出约束，使模型返回统一的数据格式，便于后续 Python 程序进行解析、排序和可视化。

## 4.4 Web 自动化与数据采集

招聘岗位自动采集部分采用 DrissionPage 等自动化技术，实现招聘页面访问、岗位搜索和数据提取。系统根据用户画像生成的岗位关键词自动设置搜索条件，并对获取的岗位信息进行统一处理。相比人工复制岗位信息，该方式能够提高岗位数据获取效率，并为后续大规模岗位分析提供数据基础。

## 4.5 数据分析与可视化

系统使用 Pandas 和 NumPy 完成岗位数据清洗、转换和统计分析，并使用 Matplotlib、Seaborn 等工具对岗位数据进行可视化。通过岗位数量、薪资、工作地点、学历要求、经验要求、行业分布和匹配得分等指标，可以从整体市场和单个岗位两个层面对招聘数据进行分析。

# 5. 技术难点与解决方案

## 5.1 难点一：PDF 简历格式问题

### 5.1.1 问题分析

用户上传的简历通常采用 PDF 格式，但 PDF 并不一定包含可直接读取的文本。部分 PDF 属于标准文本型 PDF，可以直接通过 PyMuPDF 提取文本；而部分简历实际上是由图片组成的扫描件，直接进行文本提取时可能得到空字符串。

如果系统仅采用单一的 PDF 文本提取方式，则无法处理扫描型简历，从而导致后续用户画像无法正常生成。

### 5.1.2 解决方案

针对不同类型的 PDF，本系统采用文本提取与 OCR 相结合的方式。

首先使用 PyMuPDF 对 PDF 页面进行文本提取，判断是否存在有效文本。如果能够获取有效文本，则直接进入后续的文本清洗和 LLM 分析流程；如果提取结果为空，则判断该 PDF 可能属于扫描型或图片型 PDF，此时将 PDF 页面转换为较高分辨率的图片，再利用 OCR 技术识别其中的文字。最终将两种方式得到的文本统一进入后续处理流程。

该方案能够兼顾普通文本型 PDF 和扫描型 PDF，提高系统对不同简历格式的兼容能力。

## 5.2 难点二：Token 消耗问题

### 5.2.1 问题分析

岗位匹配过程中，一个用户可能对应几十甚至上百个岗位，而每个岗位 JD 又包含岗位职责、任职要求、公司介绍等大量文本。如果将完整的用户简历和完整的岗位 JD 分别重复发送给 LLM，会造成大量重复 Token 消耗，并增加模型调用时间和成本。尤其是在对大量岗位进行批量评分时，该问题更加明显。

### 5.2.2 解决方案

本系统采用用户画像摘要 + RAG 检索 + 分阶段处理的方式降低 Token 消耗。

首先，在用户画像阶段利用 LLM 对原始简历进行总结，将较长的简历内容转化为结构化职业画像和职场报告。后续岗位分析不再反复使用完整简历，而是使用已经提炼后的用户画像作为模型上下文。其次，在岗位匹配阶段利用 RAG 对岗位进行初步检索，将大量原始岗位缩小到与用户职业方向更加相关的候选岗位。最后，再利用 LLM 对候选岗位进行深度匹配和评分。

该方案能够在保证分析效果的同时，明显减少无效 Token 的使用。

## 5.3 难点三：并发数问题

### 5.3.1 问题分析

岗位智能评分需要对多个岗位分别调用 LLM。如果采用串行方式逐个分析岗位，随着岗位数量增加，整体处理时间会明显增长，因此，采用多线程并发可以有效缩短批量岗位评分的处理时间。但并发数量过高又可能导致模型 API 请求频率超过限制，引发请求失败、超时或返回异常。因此，需要在处理速度和 API 稳定性之间进行平衡。

### 5.3.2 解决方案

系统采用线程池调度器（ThreadPoolExecutor ）实现岗位评分任务的并发处理，并通过限制最大并发数（max_workers）控制同时运行的任务数量。

同时，为提高系统稳定性，在单个岗位分析过程中增加异常捕获和重试机制。当模型请求出现暂时性错误、网络异常或接口调用失败时，系统不会立即终止整个任务，而是对当前岗位进行有限次数的重试。

该方案能够在保证系统稳定性的基础上提高批量岗位分析效率。

# 6. 项目创新点

1. LLM 驱动的语义化人岗匹配： 利用 LLM 的语义理解与推理能力，突破传统关键词匹配限制，从能力、职责、发展、背景和潜力等多个维度实现深层次人岗匹配。
2. 以用户画像为核心的主动式求职：基于简历与用户偏好构建动态职业画像，并自动生成职业方向和岗位检索关键词，实现从 “用户主动筛选岗位” 向 “系统基于用户特征辅助发现和匹配岗位” 的转变。
3. 职业规划与岗位推荐一体化：将用户画像、职业规划、岗位采集和智能匹配进行联动，使职业定位结果能够直接指导岗位搜索和岗位选择，形成完整的求职辅助流程。
4. RAG + LLM 的分阶段智能分析：采用 “RAG 检索筛选 + LLM 深度推理” 的方式，从海量岗位中快速筛选高相关岗位，再进行多维度智能评分，在提高匹配效率的同时降低模型调用成本。
5. 岗位匹配与数据分析决策融合：将智能岗位推荐与岗位市场数据可视化相结合，同时展示岗位匹配结果和市场特征，为用户提供从 “认识自己、寻找岗位” 到 “比较岗位、辅助决策” 的一体化支持。

# 7. 后续优化路线
 
 1. 动态用户画像优化： 融合用户浏览、收藏、投递及反馈数据，持续更新用户画像，提高个性化推荐能力。
 2. 智能匹配模型优化：建立标准化岗位与技能标签体系，结合历史反馈优化匹配规则和 LLM 评分机制，提高人岗匹配准确性。
 3. 岗位知识库建设：构建岗位、职业、技能及行业知识库，完善 RAG 检索能力，为职业分析和发展规划提供更丰富的知识支撑。
 4. 系统性能与数据采集优化：优化爬虫稳定性、数据清洗、RAG 检索、LLM 并发及 Token 控制，提高系统运行效率和大规模岗位处理能力。
 5. 向智能求职 Agent 演进：引入 Agent 的任务规划与工具调用能力，实现从用户画像、岗位搜索、智能匹配到求职决策的自动化执行，提升系统整体智能化水平。
